### #14 `policy=1` 被误显示为风险标记（0.2.2 修复）

- 反馈人：`silver-kin`，2026-11-10。
- 现象：11/05 之后的记录详情出现「风险标记 policy=1」，但记录状态是“已通过”，
  平台检查 5/5。
- 根因：`policy` 是服务器下发的**规则集编号**（1 = 学分跑），详情接口原样回显；
  旧前端把所有非零 `policy` 当反作弊标记。
- 修复：
  - 风险标记只读 `is_cheat` / `step_freq_status`；
  - `policy` 单独显示为「规则集 policy=1」，带 tooltip；
  - 静态回归防止 `if(+x.policy) risk.push` 重新出现。
- 依据：`app/frontend/js/app.js::selectRecord()`、
  `app/tests/test_record_obs_and_rules.py::test_record_detail_policy_is_the_rule_set_not_a_risk_flag`、
  `docs/decisions.md` §25。
- 回复要点：`policy=1` 不代表清算；真实风险字段见
  [`20-risk-rules.md`](20-risk-rules.md)。

## 2. 高频 FAQ

### Q1：详情里的 `policy=1` 是风险标记吗？

不是。它是规则集编号（1 = 学分跑）。0.2.2 起单独显示为「规则集」。
风险看 `isCheat`、`stepFreqStatus`、`status`、`normalRun`、`reasonList`。

### Q2：会被清算吗？

无法保证。服务端反作弊是回溯性的；`policy=1` 本身不代表异常。如果
`isCheat=1` 或 `stepFreqStatus≠0`，再按原因列表分析。

### Q3：为什么记录状态“已通过”，详情却是红色？

0.2.1 及以前的前端 bug：详情页把 `policy` 当风险。升级到 0.2.2 即可。
记录本身没有变。

### Q4：为什么步频/配速不通过？

各校规则不同，且平台会按 `runRuleModel` 判定。先看设置页「从服务器读取」的
学校规则，再看记录详情的原因列表。社区里的“8–40”“60–300”等数字互相冲突，
不能当平台常量。

### Q5：为什么安装包提示“未知发布者”/被杀软报毒？

没有代码签名，只有 SHA-256；SmartScreen 会提示未知发布者。Nuitka 编译的
Windows 二进制也经常被误报（Nuitka 官方文档也说明这是常见现象）。
核对 Release 页的 SHA256，必要时加信任。

### Q6：为什么轨迹是空的 / OBS 404？

记录详情里 `jsonFromObs=1` 时，轨迹在 OBS；对象不存在或被清理就只剩统计。
OBS 失败只影响轨迹，不影响距离/配速/平台检查项。

### Q7：升级后为什么要求重新登录？

设备指纹迁移、token 失效或换机都会触发。登录/提交/OBS 必须共用同一份指纹；
迁移前会备份旧指纹。

### Q8：公告里的加群暗号是什么？

`皮卡丘`。公告正文不写群号，直接扫二维码进群。

### Q9：为什么提交后没有自动重试？

超时 = 未知状态，可能已经入库。自动重试会重复记录，所以用回执锁住时段，
先只读对账。

### Q10：每日上限和学校上限有什么区别？

本地 `--max-per-day` 默认 2 次，是工具硬闸门；学校上限是合格模型的提醒，
不阻止提交。两者不要混。

## 3. 回复纪律

3. 不把社区规则当成平台常量。
4. 涉及凭据、token、DeviceId、坐标，提醒用户不要贴；让用户用诊断包。
5. 作者自己的征求意见 issue（#9）不自动评论。
6. 修复类回复带上版本号和升级方式。
