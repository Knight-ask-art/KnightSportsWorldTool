## 2. 启动

```powershell
# 浏览器 UI（推荐）
python run.py --port 65520

# 不自动开浏览器
python run.py --port 65520 --no-browser

# 桌面壳（需要 pywebview）
python app.py

# 跳过单实例互斥量（仅开发调试；两个实例会共用 data/）
python app.py --allow-multi

# 指定数据目录（默认 app/data）
python run.py --port 65520 --store D:\somewhere\data
```

只监听 `127.0.0.1`，不对外网开放。

## 3. UI 面板（七页）

新 UI 是唯一入口：`frontend/index.html`，由 `python run.py` 或 `app.py` 打开。
启动后先显示**登录页**：没有本地会话时必须登录，成功后才进入七页；已有有效会话
会自动进入；点「退出登录」会回到登录页。登录成功会自动开启 probe-only token 保活
（保活用的密码只在内存）。登录页可勾选「记住密码」：勾选后账号和密码使用 Windows
DPAPI 加密保存在本机 `data/saved_login.json`，只有当前 Windows 用户能解密；不勾选
则不会保存。没有真实数据时显示空状态，不生成演示记录。

登录页必须勾选「我同意并认真阅读了《免责声明》」，未勾选无法登录；点《免责声明》
可查看完整协议。接受状态记录在 `data/ui_state.json`（版本号 + 时间），不写进账号
文件。升级后如果本机还没接受当前版本，已有会话会先被强制退出一次，勾选后才能重新
登录。登录页、侧栏和「设置 → 关于」固定显示防倒卖提示：本项目完全免费开源，付费
购买请立即申请退款并举报商家。

本机采用**一号一设备**：第一个登录成功的账号与这台机器绑定，退出登录不会释放；
在同一台机器上登录另一个账号会被拒绝，并提示「为防止恶意使用软件，软件请一号一
设备绑定」。同一账号可以反复登录；更换设备指纹不影响绑定。需要把机器转给他人时，
请按 `docs/kb/46-account-guard.md` 的说明重置本机绑定，不要在 UI 里提供入口。

### 画路线

1. 登录后打开跑步页；围栏和点位自动加载（有缓存）。点「刷新」强制拉取。
2. 选「手绘」，在地图上**单击加点**；右键删点；第一个落点就是起点。
3. 闭合开关默认开：3/4/5 个点都会首尾相连成圈；关闭时保留开放折线。
4. 也可以选「自动」（按当前点位绕圈）、「田径场」（200/300/400m）或
   「导入」（GPX / GeoJSON / JSON / CSV，本地解析）。
5. 需要贴真实道路时点「吸附」（要 `JHP_AMAP_KEY` 或 `--amap-key`）。
6. 目标距离默认 **0**，画好路线后按线路长度自动填写：开放路线填全长，闭合路线
   填单圈长度；手动改过之后保留你的值，不会覆盖。删除最后一点或
   清空路线会回到 0。闭合路线绕几圈由目标距离决定。
   点位不会在绘制过程中反复请求；关画笔、切出「路线」页、导入/载入路线、拖动结束
   或手改距离后，按最终距离请求一次。若 5 分钟预算/10603 不允许重拉，点位徽标、
   围栏 chip 和检查表会显示「点位按 X km 加载，当前目标 Y km」，点该检查项可手动刷新。
7. 提交前检查 token、点位、打卡点覆盖、围栏、校规、跑步冻结期、人脸抽检和距离要求；
   未经过点位时后端可自动插入（`snap_route`）。打卡点命中半径由后端下发
   （官方是 25 m），页面上显示的就是实际判定用的半径。
   冻结期只标黄提醒、不阻止提交；人脸抽检会阻止提交；距离低于学校要求时该行
   保持未勾选，避免提交一条不计入的记录。

### 学校要求自动读取

登录后如果本地还没有保存学校要求，工具会自动调用服务器的
`runModePolicy`，把 `runRuleModel` 里有明确单位的字段填进「设置 → 学校要求」
并保存：

| 服务器字段 | 表单字段 | 换算 |
|---|---|---|
| `minDistance` | 最低距离 | 米 → km |
| `minRunTime` / `maxRunTime` | 最短/最长时长 | 秒 → 分钟 |
| `speedTop` / `speedBottom` | 配速下限/上限 | 分钟/km（原值） |
| `stepTop` / `stepBottom` | 步频下限/上限 | spm（原值） |
| `validTime[0]` | 有效时间窗 | `HH:MM` |

不猜的字段：`dayGoal`（每日目标，不是单次上限）、`weekCountGoal`、
`minSteps` 等，只在提示里显示，不写进规则。服务器返回多个时段时只填第一个，
并在提示里说明。已经保存过规则时不会自动覆盖；设置页的「从服务器读取」可以
手动更新（确认后只覆盖服务器返回的字段，其余保留）。如果主动把所有项清空并
保存，会关闭模型并停止后续自动读取；需要恢复时点「从服务器读取」。

### 个人主页与违规自查

「我的」页把账号资料、本学期进度和违规记录放在一起：

- 资料优先来自 `api/v70400/user/info`（7.4.0 换的路径；旧 `v70100` 只在 404 时
  回退），返回姓名、昵称、年级班级、学校、校区、
  身高/体重、uid/unid；接口失败时回落到本地会话，并明确标成「本地资料」。
- 本学期进度复用学期汇总 / 个人完成度，和「总览」是同一套数字。
- **违规自查**必须手动点「查询违规」，不会在登录或翻页时自动请求。
  状态分四种：`未发现 / 有记录 / 结果未知 / 查询失败`；
  `结果未知` 表示服务器没有返回个人违规字段，**不会显示成“正常”**。
  查询结果带查询时间，超过缓存时间会标「结果已过期」。
- 结果只代表本次只读查询，最终判定以官方 App / 学校为准。

### 补跑日期与开始时间

「跑步 → 参数」里的 **提交日期 / 开始时间** 控制记录落在哪一天：

- 点开日期按钮是一个小的日历，直接选**具体日期**（北京时间日历日，
  不是 72 小时）；只能选最近 3 天（含今天），范围外的日期是灰的。
- 开始时间必须在 **09:00–22:00**；留空则在该时段内随机。
- 整段跑步都要在 22:00 前结束；当天的记录也不能排到“现在”之后，
  否则模型和提交都会拒绝并说明原因。
- 打开页面时如果今天已经放不下这次跑步（例如还没到 09:00），
  日期默认落到昨天，避免一进来就是一条必然失败的记录。
- 学校要求里的 **每日上限** 按**所选日期**统计：选 10 月 20 日就查 20 日
  已跑几次。次数优先取服务器记录；服务器读不到时模型会明确显示
  “无法确认”，而不是假装 0 次。
- 超过学校上限时**只提醒**（模型 `warn` + 琥珀色感叹号），不会因此拒绝
  提交；是否还有效由学校/服务器决定。

> 服务器是否接受补跑的历史日期没有公开证据（上游 README 写“前 3 天”，
> 但仓库把 `#64 时间限制根因未确定` 标为未解决）。工具只负责把时间写对，
> 不能保证服务器一定收。详见 `docs/decisions.md`。

> 围栏和检查只是**提示**；越界或漏点的记录很可能被判无效。

### 提交回执与只读核对

「记录」页顶部是**提交回执**：`待确认 / 结果未知 / 已受理 / 已拒绝`。
提交超时后不要重复点提交；点「只读核对未决」，它会用最近记录按开始时间
（±3 分钟）和距离（±120m 或 8%）匹配，匹配到才把回执改成「已受理」。
**核对不会重发、不会补传 OBS**；没匹配到就保持未决。

### 网络诊断（仅提醒）

「跑步 → 提交」里的「网络诊断（仅提醒）」会显式查询一次公网 IP 归属地，
显示校区城市、出口 IP 城市、本机时钟与服务器时间、是否同城。它只在你点击时
联网；不点就不会查，也**不在提交检查表里**，不影响提交按钮。

江门校区用广州出口 IP 是最常见的暴露点，建议真实提交前先看一眼。出口城市
对不上只作提醒：运营商省级 NAT 很常见，最终以服务端为准。

**时钟偏差由软件自己处理。** 工具会读取服务器时间（`GET
api/v3/getserver/gmttime`；响应体不可用时回退到 HTTP `Date` 头），在进程内
维护一个偏移量；生成轨迹、签名请求和页面显示都使用校正后的时间。不会修改
Windows 系统时间，也不需要你手动校准。偏移只缓存在本机 `data/clock.json`
（12 小时内复用），不写注册表、不改系统时间。只有在服务器时间完全读不到时
才按本机时钟继续，登录或提交前会自动再试一次。

### 记录里的城市（address）

官方客户端在上传前会把**起点 GCJ 坐标**做一次逆地理编码，把得到的城市写进
`SportRecord.address`（`OutdoorRunViewModel.saveStartPointToDb()` →
`MapLogKt.getCity()`）；拿不到就写空串。本工具按同一链路处理：

1. 有高德「Web 服务」Key 时，逆地理编码轨迹首点，取城市（直辖市回退到省份）；
2. 没有 Key 或请求失败时，回退到校区/学校名里能识别的城市；
3. 仍然识别不到就提交空串，**不会**再把“学校名 + 校区名”当城市提交。

要在记录里显示真实城市，建议在「设置 → 网络」填入高德 Web 服务 Key。

### 提交前审计 / 只读核验

提交页的「提交前审计」对**上一次预览或生成的数据**做 7.4.0 形状检查：
27 个轨迹字段、`lat/lng=-1`、无 `steps`、OBS 11 键、窗口/分段/圈合计、
`queueNum`、fivePoint、围栏和 `validate_run_data`。生成路径完全离线；
记录审计只读详情。审计失败时不要提交，先按卡片里的第一个失败项修。
卡片默认只列出失败和警告，点「显示全部」可展开通过项；「只看问题」可收回。

提交结果卡上的「只读核验」读取 `v70320` 详情，显示 `complete`、
`isCheat`、`reasonList`、OBS 轨迹和图表序列的逐项时间线。它**不会重发**，
也不会补传 OBS；结论是 `ok/warn/issue/unknown` 四态，不把空 200 当成功。

服务器错误会经过 `application.errors` 解释：例如 `11016` 是时间窗、
`10003` 是极验票据信任不足、`10603` 是点位冷却、超时则先查回执而不是重提。

### 预设 / 统计 / FIT / 诊断包 / 巡检

- **预设**：保存距离、配速、步频、海拔、路线、时间等表单字段；不保存
  token/密码。最多 30 条，存在 `data/presets.json`。
- **统计**：最近 12 周跑量、平均配速、步频、提交成功率、失败原因 Top N；
  服务器记录读不到时明确标 `source=local`。
- **FIT**：从一条服务器记录生成标准 FIT，返回下载数据；不写盘。
- **诊断包**：ZIP 内含诊断文本、最近审计、时钟、脱敏设置和最近回执；
  token/密码/完整坐标/签名 URL 会被双重清洗。
- **巡检**：只读检查 token、冻结剩余时间、今日次数、最近记录、时钟偏移和
  最近回执；不触发提交。
- **回放**：记录详情的「回放」用本地 Canvas 播放轨迹、配速/步频/海拔曲线和
  打卡点；不发任何请求，只使用已经读到的详情数据。

### 真实性档案（暂停 / GPS / 坡度）

暂停与坡度默认关闭；GPS 默认 `urban`（与 v0.1.7 的随机漂移一致）。

| 选项 | 作用 | 注意 |
|---|---|---|
| 中途暂停：随机 | 全程 1–2 次、每次 20–90 s，只推进墙钟 `gainTime`/`stopTime`；`totalTime` 仍是活跃秒 | 窗口仍按活跃时钟分配，不是逐点真机复现；`manual` 仅 CLI 支持 |
| GPS 轨迹波动：自然 | 默认；`count` 53–79、`radius` 2.5–15 m 慢游走 | 与 v0.1.7 行为一致 |
| GPS 轨迹波动：非常稳定 | 固定 `count=60`、`radius=5`，便于回归 | 测试档，不用于真实提交 |
| GPS 轨迹波动：模拟信号差 | 短时 `count` 4–8、`radius` 20–40 m | 保留点数，保证窗口/圈合计守恒 |
| 按坡度调整配速 | 仅在提供海拔模板时启用，按坡度重分每公里用时 | 没有模板不发明山丘；总时长不变 |

### 跳过打卡点（学校没有打卡点）

「跑步 → 路线」里的 **跳过打卡点（无点位学校，非官方自由跑）** 勾选后，
提交时不再拉打卡点，仍会检查围栏（如果学校配置了）、距离、配速、时间窗和
学校策略。学校策略里若有必经点，后端会明确拒绝，不会假装成功。

这个勾选框不是官方自由跑：官方自由跑是 serviceType=3 / sportType=4 的另一条
上传链路，本工具目前不支持。普通提交遇到服务器返回空打卡点时默认停止，只有
你确认学校确实没有点位并显式勾选后才继续。

### 学校没有围栏 / 地图不是我的学校

部分学校不配置跑步围栏，官方客户端会直接放行。工具遇到空围栏也不再拒绝
提交，而是按已保存的校区坐标生成轨迹；如果服务器也没有返回可用中心：

1. 把跑步页地图拖到你的学校；
2. 点「设为校区」（坐标只写入本机会话，不上传）；
3. 再点「刷新」拉打卡点；没有打卡点时仍需显式勾选“跳过打卡点”。

多校区学校：`runModePolicy` 返回的 `runAreaModels` 自带 `fenceIds`。工具先用
当前账号的 `campusName`/`schoolName` 匹配跑区名，A 账号（广软）和 B 账号
（广州）各自自动落到自己的跑区；匹配不到才回退官方 `selectedPosition=0`。
多跑区时也可以在跑步页下拉框手动切换，无效跑区显示为灰色不可选。选择按
`uid:unid` 存进 `data/ui_state.json`，下次登录/重启自动恢复（后端会用当前
`runAreaModels` 再校验一次，失效则回退自动匹配）；下拉第一项「自动（按账号
校区）」会清空手动选择并重新按校区名匹配。跑区拥有的
全部围栏都会保留，任意一条包含轨迹即算在区域内。选中的跑区 id 会作为
`runAreaId` 随打卡点请求发送。没有跑区数据时使用全部围栏；围栏优先信
`runModePolicy`，只有它返回 `null`/缺段时才回退一次
`getGeoFenceForRun`（冻结账号实测会这样），明确返回空列表则视为无围栏。

### 跑步页操作细节

- **提交结果卡**：成功、失败、结果未知都会留在「提交」页。结果未知时提交按钮
  锁定，点卡片上的「去记录页只读核对」运行 `real_reconcile_receipts`；核对完成
  后自动解除锁定，并说明是否在服务器最近记录中找到匹配项。
- **检查表**：带真实跳转目标的检查项可点击（token → 账号、学校要求 → 设置、
  点位/围栏 → 路线、距离/日期/时间 → 参数、当日次数 → 记录）。网络出口已移出
  检查表，只在「网络诊断（仅提醒）」卡片里手动查询。冻结期、人脸抽检等没有
  修复入口的项不再显示成按钮。
- **撤销/重做**：路线编辑保存完整快照（最多 50 个），`Ctrl+Z` 撤销、
  `Ctrl+Shift+Z` 重做；加点、删点、清空、导入、路线库载入、闭合切换、拖动
  控制点都可回退。
- **控制点**：悬停显示「第 N 点」；单击选中，`Delete` 删除，`Esc` 取消；
  按住拖动松手后重新计算路线长度、目标距离和检查表。
- **点位冷却**：10603 冷却期间「刷新」按钮置灰并显示「冷却 Ns」，每秒递减，
  到 0 恢复；冷却不会跨账号（按 `uid:unid` 隔离）。

### 路线库 / GPX

- 路线从 `localStorage` 迁到本机 `data/routes.json`；换端口或用 exe 都不会丢。
- 「路线库」支持导入 GPX/GeoJSON/JSON/CSV，选中路线或当前路线可导出 GPX。

> 采集与样本库属于内部研究能力，已移出产品界面与 bridge API，
> 见 `private/README.md`；公开版本不提供该功能。

### 学期进度与 14 天计划

总览的「本学期」显示服务器返回的已完成/目标/剩余天数和完成度；读不到时
显示失败而不是 0。「未来 14 天」来自 `real_plan`，点「填」会把距离/配速/
步频填进跑步参数；已完成的日期会标灰。

### 记录详情轨迹

「记录」右侧详情里有一张小地图：轨迹、起点/终点、打卡点绿/红。可导出
GPX 或把这条轨迹存进路线库。地图瓦片和主地图一样按 z18 封顶放大。

有些记录是官方 App/本工具的 OBS 轨迹（详情字段 `jsonFromObs=1`），数据库里的
`allLocJson` 是空的；工具会按 `run_data/{YYYYMMDDHH}/{uuid}.json`（读不到再试旧的
`run_data/{rrid//1000000}/{rrid}.json`）读取 OBS
对象后再画图。OBS 读取失败时，距离/配速/平台检查项仍会显示，小地图下方会说明
失败原因，不会把整条详情判为查询失败。

### 检查更新

启动约 1.5 秒后静默读一次发布清单；有新版时，左下角版本号右侧出现一个下载
图标（红点）。点它可以看到更新说明并下载。

- 设置 → 关于里也有「检查更新」，失败时会写原因。
- 下载包落在 `data/updates/`，先校验大小和 sha256；点「立即更新」后自动解压、
  退出程序、覆盖安装目录并重新启动，`data/` 保留。
- 替换由后台 PowerShell 脚本在当前进程退出后完成，不会在半途覆盖正在运行的 exe。
- 清单地址默认是 GitHub raw，网络不通时自动换 jsDelivr；也可以用
  `JHP_UPDATE_MANIFEST` 指向自己的镜像。

### 4.1.2 token 保活

官方接口里**没有**文档化的 refresh-token 端点。因此保活分两层：

1. **定时探测**：每 N 小时用当前 token 请求一次最轻的 `GET user/info`
   （7.4.0 起 `v70400`，404 时回退 `v70100`）；
   成功就更新 `last_ok_at`，401/业务拒绝就把 `token_expired` 标成 true。
   这能证明 token 还活着，也能提前发现失效，但**不能保证**延长服务端固定 TTL。
2. **自动重登（可选）**：探测到失效时，用当次运行传入的手机号/密码重新登录，
   换新 token。密码只在内存，**不写入 `accounts_emu.json`**；进程重启后需重新输入。

```powershell
# 只探测一次（适合计划任务）
python -m replica.pipeline --keepalive-once

# 前台保活：每 6 小时探测一次
python -m replica.pipeline --keepalive --keepalive-interval 21600

# 失效时自动重登（密码只在内存，会出现在进程命令行里，介意就别用）
python -m replica.pipeline --keepalive --auto-relogin --user <手机号> --pass <密码>
```

UI 的「账号」页有「token 保活」卡片：选间隔、开启/停止、立即检查；
勾「失效时自动重登」会使用卡片上方的手机号/密码，这份密码只在内存，不落盘。
登录页勾选「记住密码」是另一份**独立的** DPAPI 加密存储，只用于下次打开时预填登录框，
不会被保活/自动重登读取。取消勾选会立即删除 `data/saved_login.json`。
被标记为 `disabled` 的会话（例如用户明确停用的旧账号）**不会**被探测或重登。
